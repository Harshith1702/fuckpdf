# POC-001 Notes: Native PDF Text Editing

## Overview

POC-001 demonstrated modifying a text run in a real PDF content stream without flattening, rasterizing, or whiteout overlay tricks. The edited PDF was serialized, re-parsed, and rendered before and after with MuPDF WASM, passing pixel difference validation (< 0.1% tolerance).

## What Was Hard

1. **Content stream decoding vs. stream writing in MuPDF.js:**
   MuPDF separates indirect object dictionaries from underlying uncompressed byte buffers. Reading the stream requires `pdfObject.readStream().asString()`, whereas updating requires creating a `new mupdf.Buffer()` and calling `pdfObject.writeStream(buf)`.
2. **Text operator syntax variations:**
   PDF content streams can show text via multiple operators (`Tj`, `TJ`, `'`, `"`). Handling both `Tj` (single string operand) and `TJ` (array of strings and kerning offsets) is necessary for real-world documents where character tracking or word spacing injects numerical adjustments.

## What Surprised Us

1. **MuPDF WASM speed and fidelity:**
   MuPDF WASM loaded in Node in under 50ms, rendered full 72 DPI pixmaps instantaneously, and immediately recomputed page structured text trees after `writeStream()` was called without requiring document reload.
2. **Clean separation between stream edits and document structure:**
   Because only the stream bytes inside `Contents` were edited, the xref table, page dictionary, and resource dictionaries remained intact and valid. The visual difference on the rendered page was strictly 151 pixels (0.0312% of total pixels), localized entirely to the modified glyphs.

## Next Risks & Challenges for Phase 1 and Phase 2

1. **Complex Font Subsets and Encodings:**
   The POC used a standard 14 font (Helvetica) with WinAnsiEncoding. Real-world PDFs frequently use custom CID/Type0 fonts with embedded TrueType subsets where character codes do not match standard ASCII or Unicode. Phase 3 & 4 will require parsing `/ToUnicode` CMaps and `/Widths` arrays.
2. **Coordinate Space Mapping:**
   PDF user space has its origin at the bottom-left, while browser DOM / canvas coordinates have origin at the top-left. Text bounds detection in Phase 2 must correctly transform via Current Transformation Matrix (CTM) and Text Matrix (`Tm`).
3. **Multi-stream Pages:**
   Some PDF generators store page content across an array of indirect stream objects rather than a single stream. The interpreter must concatenate streams in order during semantic reconstruction while mapping byte offsets back to their origin stream.
